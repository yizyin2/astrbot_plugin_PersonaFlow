# PersonaFlow（人格关系流）3.0

[![AstrBot](https://img.shields.io/badge/AstrBot-Plugin-violet)](https://github.com/AstrBotDevs/AstrBot)
[![Version](https://img.shields.io/badge/version-3.0.3-blue)](https://github.com/yizyin2/astrbot_plugin_PersonaFlow)

让 AstrBot 里的角色记得人、不同会话之间不失忆，并且全部在一个可视化面板里管理。

## 它解决什么问题

**你是不是还在担心，每次 `/new` 一下，bot 就忘了群友和它是什么关系？**

PersonaFlow 把"它认识谁、对谁是什么印象、以前聊过什么"存进独立的记忆库，每次请求时写进人格提示词。对话历史清空了，关系和记忆还在。

**想让 bot 记得不同群里的消息和私聊消息？**

用路由把这些群和私聊指到同一个上下文库，它们就共用一份对话上下文。在私聊里告诉它的事，到群里问它也答得上来。

## 功能一览

- **人格记忆**：人物印象、全文记忆、自动压缩。多个 Bot、多个人格各用独立数据库。
- **档案路由**：按 Bot + 人格 + 会话决定用哪个记忆库、上下文存到哪里；能直接读写 AstrBot 自己的会话人格和配置文件路由。
- **独立上下文库**：多个群和私聊共用一份上下文，数据存在插件自己的库里，与 AstrBot 的对话数据分开。
- **管理面板**：路由图、记忆库、上下文库、日志和全部设置，保存即生效。

想让 bot 看懂整个群、自己决定什么时候开口，请配合 [群聊感知 GroupSense](https://github.com/yizyin2/astrbot_plugin_GroupSense)。它在 2.x 时并在本插件里，3.0 起拆成了独立插件，见下文「和群聊感知一起用」。

需要 AstrBot ≥ 4.29。

## 安装与升级

1. 把插件目录放进 `data/plugins/astrbot_plugin_PersonaFlow/`，或在插件管理里安装，然后重载。
2. 打开插件详情页里的 **PersonaFlow 管理面板**。所有设置都在面板里修改，保存即生效。
3. 到「路由」页添加一个档案：选 Bot 和人格。之后这个人格在这个 Bot 上的会话就开始有记忆了。

从 1.x 升级时，首次启动会自动导入旧配置，结果显示在面板「总览」里。

从 2.x 升级到 3.0：档案、记忆库、上下文库都不用动。2.x 里的群聊感知已经拆成独立的群聊感知插件，**如果你在用它，请同时安装群聊感知 GroupSense 1.0**，它第一次启动时会从本插件的数据目录导入原来的设置、群聊记录和图片。本插件会把 2.x 的群聊感知设置原样留在 `settings.json` 的 `legacy_sense` 里供它导入，不会再用到。

AstrBot 自带的插件配置页只保留一个总开关。

## 管理面板

| 页面 | 用途 |
| --- | --- |
| 总览 | 状态检查（冲突的设置、未生效的档案等）、迁移报告、各档案概况、最近活动 |
| 路由 | 一张从 Bot 到会话的管线图；档案的增删改；改会话的上下文去向和 AstrBot 路由；路由测试 |
| 人格记忆 | 每个档案的人物印象、全文记忆、对话记录、关系图、最终人格提示词；手动总结和压缩 |
| 上下文库 | 新建和删除上下文库；每个库的对话时间线、断点、下次请求会带上的范围；编辑、导入、导出 |
| 日志 | 结构化事件和文本日志，按级别、类别、会话筛选，可实时滚动 |
| 设置 | 人格记忆、上下文库、日志的全部参数 |

## 路由

路由页是一张从左到右的图：

```
Bot  →  人格  →  记忆库（档案） →  上下文  →  群聊 / 私聊
```

**档案**是路由的核心：一个档案 = Bot + 机器人账号（可选）+ 人格，带生效范围（哪些群、是否包含私聊）。它决定两件事：

- 用哪个记忆库：范围内的会话共享人物印象和全文记忆；
- 上下文存到哪里：某个上下文库，或者不接管（仍由 AstrBot 保存）。

常用操作：

- **点最右边的会话**：把它的上下文改到某个上下文库或"不接管"，改它在 AstrBot 里的人格和配置文件，或把它移出档案。
- **拖动**：还没进入任何档案的会话，直接拖到档案上就加入了。
- **切换默认去向**：点上下文节点上的"切换"，档案里没有单独指定的会话都跟着走。
- **路由测试**：在页面底部输入 Bot、人格和群号，看它会走到哪里。

### 会话为什么没进档案

档案是按**会话实际生效的人格**匹配的。AstrBot 决定人格的顺序是：自定义规则里给会话强制指定的人格 → 当前对话用 `/persona` 切换的人格 → 配置文件里的默认人格。

所以想让某个群稳定地走某个档案，最好在会话规则里给它强制指定人格；只靠 `/persona` 的话，`/new` 之后会掉回默认人格。

这一步可以直接在路由页完成，不用去翻 AstrBot 的设置：

- 点会话卡片，菜单里的「AstrBot 路由」会显示它现在的人格来自哪一层、走的是哪份配置文件，点进去就能改。
- 把人格不匹配的会话拖进档案时，面板会问你要不要把它的人格改成档案的人格，确认后一并改好。

> 这两项操作会修改 AstrBot 自己的设置：改人格写的是「会话管理」里该会话的规则，改配置文件写的是「配置文件」页的路由表。插件只在你点了保存或确认之后才写，只影响这一个会话，不会改配置文件本身的内容，每次修改都会记进日志页。

没进档案的会话，鼠标停在卡片上会显示原因。也可以在会话里以管理员身份发 `/osn profile` 查看。

多个账号共用一个 Bot 适配器时，给每个账号各建一个档案并填上账号 ID。有冲突的档案（重复、账号选择重叠、共用同一个数据库文件）不会生效，面板里会标出原因，其他档案不受影响。

## 人格记忆

在人格提示词里可以指定记忆的插入位置：

```text
你是一个叫“小周周”的 AI 助手。

你认识的人：
{Impression}

以前的聊天记忆：
{Memory}
```

没写占位符时，对应内容追加到人格末尾。插件每次都从 AstrBot 当前的人格模板重新组装，修改人格后下一条请求就生效，也不会修改 AstrBot 里的原始人格。

- **人物印象**：每位用户对话满一定轮数后，让模型总结与他的关系和印象。
- **全文记忆**：范围内累计满一定轮数后，把最近的对话总结成一条记忆；条数超过阈值时把最旧的一批合并成一条。
- 可以在设置里指定单独的「总结模型」，让总结用便宜的模型。

## 独立上下文库

1. 在「上下文库」页面点「新建上下文库」，选它属于哪个档案，起个名字。
2. 到「路由」页，点会话选这个库，或在默认去向上点"切换"选它。

指到同一个库的群和私聊共用一份对话上下文，每一轮都标了来源，模型能分清哪句话是在哪说的。接管后，AstrBot 的对话数据里不再有这些会话的内容（只保留一条空记录用于选择人格）。

需要知道的两点：

- 共享之后私聊内容会进入群聊请求，模型可能在群里提到。可以在档案里关掉「私聊内容对群聊可见」。
- 每次请求会多带跨会话的历史，token 用量会增加。窗口大小在「设置 → 独立上下文库」里调，更早的内容由全文记忆承担。

`/reset`、`/new` 和 `/ctx reset` 在被接管的会话里只打一个断点：之后的请求从这里重新开始，旧内容还在，面板里可以撤销。上下文库和群聊的重置只允许 AstrBot 管理员操作。

## 和群聊感知一起用

[群聊感知 GroupSense](https://github.com/yizyin2/astrbot_plugin_GroupSense) 负责"群里该不该开口、群里发生了什么"，本插件负责"它记得谁、记得什么"。两个插件互不依赖，各装各的都能用；一起装时会自动配合：

- **判断时参考印象**：群聊感知的判断模型决定要不要回话时，会通过本插件的 `get_impressions` 接口读取机器人对群友的关系和印象。
- **上下文不重复**：群聊感知接管的群，主模型每次已经能看到最近几十条群聊记录。上下文库会跳过已经在群聊记录里的本群对话，也不再给这些消息加来源前缀；群聊感知看到上下文库接管了对话历史，就不再去裁剪 AstrBot 的对话历史。

两边通过事件上的两个标记配合（`pf/keys.py` 有说明），钩子的先后顺序是：本插件注入人格（优先级 0）→ 群聊感知标出受管群（-90）→ 本插件的上下文库（-100）→ 群聊感知注入群聊记录（-110）。

## 指令

| 指令 | 作用 |
| --- | --- |
| `/osn profile` | 当前 Bot、账号、人格命中的档案和数据库 |
| `/osn check [页码]` | 查看人物印象 |
| `/osn checkmem [页码]` | 查看全文记忆 |
| `/osn del <用户ID>` | 删除某人的印象和对话记录 |
| `/osn clearmem [条数]` | 删除最近几条或全部全文记忆 |
| `/ctx` | 当前会话使用的上下文库和窗口大小 |
| `/ctx reset` | 在上下文库里打断点，从这里重新开始 |

`/osn` 和 `/ctx` 的查看功能仅 AstrBot 管理员可用。

## 供其他插件调用的接口

```python
metadata = self.context.get_registered_star("astrbot_plugin_PersonaFlow")
personaflow = metadata.star_cls if metadata and metadata.activated else None
if personaflow is not None and getattr(personaflow, "API_VERSION", 0) >= 1:
    impressions = await personaflow.get_impressions(event, ["123456"])
    profile = await personaflow.resolve_profile(event)
```

| 接口 | 说明 |
| --- | --- |
| `API_VERSION` | 当前为 `2`，v1 的两个接口保持不变 |
| `await get_impressions(event, user_ids)` | 只读获取指定用户的关系、印象和对话次数；不在范围或出错时返回空字典 |
| `await resolve_profile(event)` | 返回该事件对应的记忆配置；不在范围时返回 `None` |

## 数据

都在 `data/plugin_data/astrbot_plugin_PersonaFlow/`：

| 文件 | 内容 |
| --- | --- |
| `settings.json` | 全部设置和档案 |
| `profiles/*.db` | 各档案的记忆库（人物印象、对话记录、全文记忆） |
| `sessions.json` | 见过的群和私聊，路由页用 |
| `context.db` | 独立上下文库 |
| `logs.db` | 日志 |
| `backups/` | 面板修改记忆库前自动留的备份（每个库保留最近 5 份） |
| `sense/` | 只有从 2.x 升级的才有：2.x 群聊感知的群聊记录。群聊感知插件导入后，确认无误可以删掉 |
